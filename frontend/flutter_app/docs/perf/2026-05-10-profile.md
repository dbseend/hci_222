## Findings

1. `ScanScreen` can stay indefinitely in `_isInitializingCamera` on macOS/profile when camera startup does not resolve. Add a timeout around `availableCameras()` and `controller.initialize()` and show a retry/fallback state.
2. Community filtering rebuilds twice per accepted change: `_onFilterChanged()` calls `setState()` for filter strings, then `_applyFilterAndSort()` calls `setState()` again for `_visibleFeed`.
3. Filtering normalizes strings repeatedly for every item and every query. With larger local data this becomes avoidable CPU work.
4. `_FeedCard` recomputes classifier, percent diff, and currency strings on every rebuild. This is fine for the MVP sample, but it will amplify jank once images or larger lists are added.
5. Current macOS integration-test timeline is blocked by VM Service websocket access. If macOS profile automation is needed, add the needed macOS network client entitlement for profile/debug or run the same test on iPhone/Android where the VM service connection works.

## Recommended Fixes

1. Fix Scan readiness first: add camera init timeout and fallback UI. This is the only observed hard fail.
2. Merge Community filter state updates into a single `setState`.
3. Store normalized searchable fields on feed items or build a lightweight view model once when posts load.
4. Precompute card display values when the visible feed is produced if list size grows past the MVP sample.
5. Repeat the run on a connected iPhone with `flutter run -d <udid> --profile`, then capture DevTools Performance metrics for FPS, janky frames, build P95, raster P95, and memory peak.
